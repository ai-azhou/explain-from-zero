# explain-from-zero

把你一直没弄懂的东西，从零讲到你真正懂，做成一段能打开、能亲手试、能留着看、能转发的讲解短片。

## 它会怎么做

1. **先回你一句**：用两三句话直接回答你卡住的那一点，说它打算做成什么、大概要多久。方向不对，你可以马上纠正。你发了图片、PDF、音视频的，它会先确认自己真的读得到：有的平台不管模型能不能看图都让你上传，有的模型其实只读文字。读不了或只读到一部分，它在这第一句里就告诉你是哪一份、你可以怎么办（把字复制给它、换个能看图的模型、同意的话装个识别文字的小工具），不会假装看过、照着「一般情况」编。
2. **查资料**：每条结论都要真打开过原文、原句撑得起；动手前先把原句和它的大白话转述并排对一遍，免得把「通常」说成「一定」。
3. **做成品**：一个单文件网页，打开就自己往下播，像看一段有配乐的短片；能暂停、回看、跳到任一步。最难跨过的那一步会停下来请你亲手试一下（点一点、拖一拖、先猜再揭晓），你不动手，它就自己演示一遍再接着播。画的是例子里的具体东西（那扇门、那本账、那片天）；风格它会先列五个候选，再挑最合这道题的一个，颜色从题目里推。要发群、给孩子看、要投屏时，可以做成视频。
4. **交付前自己打开看一遍**：从头连着播到尾，字读不读得完、画面和字说的是不是一回事、亲手试那一步能不能用、声音会不会跟着暂停；然后告诉你文件在哪、怎么打开、还差什么。

适合：学习里卡住的概念（负负得正、勾股定理、三门问题）、生活里的现象（天为什么是蓝的、钢船为什么能浮）、工作里的道理（赚钱的公司为什么会没钱倒闭、上下文窗口是什么），以及看不懂的新闻和说明书。

## 安装

```bash
npx skills add ai-azhou/explain-from-zero
```

- 加 `-g` 装到全局，所有项目都能用。
- 加 `-a claude-code`（或 `codex`、`cursor`、`gemini-cli` 等）只装给指定的 AI 助手。

## 用法

在问题前面加一句「用 explain-from-zero：」最稳，例如：

- 「用 explain-from-zero：三门问题为什么换门更好？我跟朋友吵起来了」
- 「用 explain-from-zero：新闻说平均工资又涨了，为什么我感觉自己没涨？」（把新闻一起发过去）
- 「用 explain-from-zero：想给我家 6 岁孩子讲清楚为什么会有白天和黑夜，做成视频发家长群」

不用告诉它要什么风格，它会自己按题材定；你有想要的感觉（比如「像宇宙纪录片那样」），直接说就行。

产出是一个 `.html` 文件，双击就能打开，手机也能看，断网可用，不从网上加载任何字体、脚本和声音。浏览器不让网页一打开就出声，想听配乐就点一下页面上的声音开关。

## 它不做什么

- **你自己或家人的健康和用药、法律权利和合同、钱的决定、人身安全、心理状态的具体问题**（比如拿着自己的体检单问「我是不是有问题」、问「这只股票要不要跟」）：它会停下来告诉你，这类问题这个 Skill 不能帮你答得更好，问你要 AI 按它自己的方式回答，还是这次不答。原因：我们反复测试过，讲解规则压不住模型在这类问题上替人下结论，讲错的后果太重。纯原理的问题（「抗生素为什么治不了感冒」）照常讲。
- 可能伤害自己或他人的请求、正在发生的危险：交给 AI 本身和平台的安全规则处理。
- 不替你在电脑上装东西：需要什么工具，先说清楚要什么、为什么，你同意才装。
- 公司内部、没公开的材料，不做能往外发的版本。

## 不同 AI 助手用起来的差别（我们实测看到的）

- **Claude Code**：这一版（样式库、配乐、亲手试）在 Claude Opus 5.5 上试跑过 6 道题，每份 15–20 分钟。画面最好看、讲得最完整，出处最规范；通常做完才开口，要等一阵才看到第一句。
- **Codex**：在这一版之前的两轮里最快（中位 5 分钟左右），出处核查里没查到讲错；画面比 Claude 朴素，版式容易千篇一律；回复里会提到这个 Skill 的名字和文件路径。这一版还没在 Codex 上跑过。
- **DeepSeek（DeepSeek Harness）**：更早的版本里画面常常不错，但很慢，限时 25 分钟时一半以上没做完。这一版没测。
- **还没测过的**：这一版在 Codex、DeepSeek 上的效果；网页聊天版（见下面「没有 Skill 也能用」）；电脑上真的缺工具时它会不会先问再装。

## 里面有什么

```
skills/explain-from-zero/
├── SKILL.md            入口：哪两类问题不处理、四条底线、先确认读得到你给的材料、五步做法（先回你 → 想清楚和查资料 → 讲法 → 做成品 → 交付前对一遍）
├── LICENSE.md          许可声明，装到你电脑上时跟着 Skill 一起走
└── references/
    ├── 计划.md          动手前想清楚：谁在问、拿去做什么、卡在哪种地方、讲到多深
    ├── 出处.md          查资料、事实账本、怎么核、怎么放出处
    ├── 讲法.md          从他心里的疑问讲起、一个具体例子走完全程、两层、按用途收尾
    ├── 形式.md          一段会自己播、能亲手试的片子；页面上要有的东西；按卡点挑讲法；什么时候出视频
    ├── 风格.md          先定一个世界、五个候选风格比出一个、色彩体系、六层做工、字体、声音、「不要」清单、文字去空话
    ├── 成品.md          可读、可用、准确；时间闸门；交付前打开看一遍
    └── 样式库/          18 种风格的样张（单文件网页，只有画面），教它每种风格怎么画精致
```

## 没有 Skill 也能用

（这一版提示词还没在网页聊天里系统测过。网页聊天读不到样式库，画面会比装 Skill 时朴素一些。）在网页聊天里，把 `prompt-standalone.md` 里的提示词和你的问题一起发过去。网页聊天做不了文件，网页会放在代码块里，复制存成 `.html` 打开就行。

## 背后的实验

- **题目**：从 100 道「普通人一直没弄懂的问题」题库里挑题，覆盖生活、学习、工作，另有一批慎重类问题（体检单、合同、用药、心理）。最后用 13 道冻结题验收。
- **模型**：Claude Opus 5.5、GPT-6-Astra（Codex）、DeepSeek V4.1 Flash、Kimi K3.1，每题都在全新会话里跑。
- **过程**：从一句话的 Skill 起步，迭代 15 轮、1100 多次运行。每轮由其他 AI 按同一份标准审查（讲法、观感、慎重类问题、隐私），另有 AI 打开出处逐条核对原句。

几个结论：

- 只给一句话，模型做出来的是「公众号式长文」：开头一段引用，下面密密麻麻全是字。
- 规则写得越细，画面越像同一个模板（深色底、方块圆点连线的示意图）。最后反而是删掉布局细节、只给风格词和「不要什么」，再要求「画例子里的具体东西」，画面才活起来。
- 讲错几乎都出在「把原句改写成大白话」这一步；写成品前先把原句和转述并排对一遍，讲错明显少了。
- 慎重类问题，规则写到第 4 轮，有的模型仍会替人下结论，所以这一版干脆不处理这类问题。
- 给代码骨架和带播放外壳的样张，成品就会照抄成同一个样子，像一叠幻灯片。最后只给「页面上要有什么、各自做什么」，样张只留画面，排法让模型按题目自己设计。
- 只写「背景乐轻一点、当个底」，模型做出来全是低频嗡嗡声；要写明「一段悦耳的简单旋律，先写谱再合成，跟着片子的时间线走」。
- 时间是普通人最先感受到的成本：给它一个「十几分钟先交一版能用的」的闸门以后，最慢的模型超时从一半降到一成。

## 局限

- 每次生成都有随机性，同一个问题两次结果可能差不少。
- 做视频时，配乐和音效会合进音轨；电脑上没有现成的语音合成时没有人声，是字幕版。
- AI 听不见自己做出来的声音：它只能核对声音跟不跟时间线、会不会爆音，好不好听要你自己听。
- 出处请点开核对一下原句，尤其是数字和规定。
- 自检要用到浏览器；没有浏览器的环境里，它会如实告诉你没能亲眼检查。
