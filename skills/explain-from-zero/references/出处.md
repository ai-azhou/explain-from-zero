# 查资料与出处

## 查资料

- 主线里的每条事实、数字、机制、规定，写进成品前都要找到出处；先查到，再下结论。
- 先核对用户说法里的前提：「新闻说」「听说」「群里传」的那句话，原话是什么、对不对、在什么条件下对。
- 来源说法不一致时，不挑一个顺眼的：说清分歧在哪、哪种依据更硬、为什么。
- 政策、价格、规定、统计数据，找最新的、用户所在地的；找不到就写明你用的是何时何地的版本。
- 讲用户自己的材料时，以材料原文为准，不用网上的「一般情况」替换材料里写的。
- 只查主线需要的：查到的有意思的东西，不往主线里塞。

原因：讲错的多半是把有条件的结论写成了绝对，或者条文是真的、却用错了地方。

## 写成品之前：先列事实账本

- 把成品要用到的每条事实、数字、机制、规定，先列成一张表：编号 → 来源 → 原句（保留原语言）→ 你的大白话转述。成品里的出处角标直接引用这张表（比如写在页面脚本里的一个对象里）。
- 逐条对照原句检查转述：有没有把「通常、可能、在某条件下」写成「都、一定、只」；有没有把一个来源里的特例、某种机型、某个实验条件写成通则；有没有丢掉适用的人、条件和例外。字幕、小题解析、你自己的推论也要过这一遍；原句撑不起的，标成「推论」或删掉。

原因：讲错几乎都出在「转述」这一步，不在「读」这一步；原句和转述并排写下来，大部分错当场就能拦住。

## 什么要出处

- 成品里的事实、数字、机制、规定，都要有出处。
- 用户材料里的说法、你自己举的例子、你自己的推导，和外部来源分开标明；自己编的例子标明是假设。

## 怎么核

- 出处必须是你真打开过、找到了撑得起结论的原句的来源。只看了标题或搜索摘要、页面打不开，都不算核过；没打开过的，不要对用户说「核对过」。
- 核不到就直说，把结论收窄到你核得到的范围；不编、不凑数。
- 机制写清在什么条件下成立，不写成绝对。规定、制度类写明以何时何地为准，保留适用的人、触发条件和例外。
- 为了好懂而简化时（给孩子、发群、打比方），可以少说，不能说反：简化后的那句话仍要被原句撑得住，不能把「有些」画成「全部」。
- 改写成大白话时不扩大范围：不把「更多、通常、在某条件下」改成「只、都、一定」；有例外的，说一句例外。
- 优先用一手和权威来源；百科类只当入口，不当出处。

## 怎么放

- 结论旁边放能点开的出处（不靠鼠标悬停才显示），成品结尾列参考来源；点开出处后能回到原来读的位置。
- 外文来源附原句和中文直译。
- 视频、图片这类点不开的，在片尾或图下列出处，另附一份能点开的来源清单。
