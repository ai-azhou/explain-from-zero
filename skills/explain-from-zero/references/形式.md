# 形式：一段会自己播、能亲手试的片子

成品是一段会自己播的片子，中间有让他亲手试一下的地方；不是一篇文章，也不是一叠幻灯片。按讲解的步骤分镜，从用户卡住的那一点讲到他懂；默认做成单文件网页，打开就自己往下播，不点也能看完。同一段片子加上渲染，就是视频。计划里判断另一种主形态更合这个卡点，就用那种，并在第一条消息里说一句。

**镜与镜之间要连续。** 看的人一直盯着同一样东西变过去，而不是一张换一张；分镜里每一镜都写清它怎么接到下一镜。硬切只用在需要停顿或对比的地方。

**片子里至少有一镜让他亲手试。** 除非用户点名只要视频，主线里至少有一镜让他亲手做一件事：先猜再揭晓、改一个条件看结果、点开看里面、拖一拖比大小、选一条路看后果……；放在最难跨过的那一步上。它就是片子里的一镜：播到这里，在同一个画面上、用同一套对象请他动手，他做完接着往下播。他不动手，这一镜过一会儿就自己演示一遍再往下播，所以不点也能看完；渲染成视频时，这一镜就是那遍演示。不要把它放到第一屏以外要往下滚才看得到的地方，不要放到片尾之后另起一块，也不要藏进折叠或另一个页面：看片子的人只盯着那一屏，不会想到去找。能把几种形式（分步动画、模拟、小游戏、能转的立体、原文和白话对照、分支……）自然地组合进同一段片子更好。

## 页面上要有的东西

页面上的东西包含但不限于下面这些。表里只说各自做什么、要达到什么、里面装什么；放在哪、长什么样、怎么出现和动，结合你定的风格和这道题自己定。

| 元素 | 作用 | 目标 | 呈现什么 |
| --- | --- | --- | --- |
| 主画面 | 把卡点变成看得见的变化 | 不看字也能看出这一步发生了什么；单看画面也是一件作品 | 例子里那个具体的东西和它所在的现场；这一步正在发生的变化 |
| 大字 | 说出这一步的结论 | 只读大字也能把整件事讲通 | 每一步一句话，需要时加不超过两行的解释 |
| 标注和读数 | 指出画面里该看的东西，量出它变了多少 | 看的人知道该看哪、变了多少 | 画面里具体东西的名字、数值和变化量；和事实账本一致 |
| 声音 | 让这个世界有气息，让关键的变化有分量 | 开着声音时更想看下去；关掉声音也完整看得懂 | 一段贴着题目的悦耳简单旋律当背景乐，跟着片子的时间线走；关键变化处的短音效；都在页面里用代码现场合成（见 `风格.md`「声音」） |
| 开场 | 告诉他这段片子回答什么 | 第一眼就知道答案的方向，愿意看下去 | 他的问题或一句带原因的答案，加上主画面的第一眼 |
| 收尾 | 按他拿去做什么收住 | 他能拿走：会做了、知道对自己手上的事意味着什么，或能复述给别人 | 一道换场景的小题，或回到他手上那件事，或一句能转发的话（见 `讲法.md`） |
| 播放控制 | 让他掌握节奏和声音 | 想停就停、想回看就回看、知道看到哪了；一眼看出声音开着没有，一下就能开关；不用的时候不遮住画面和字 | 播放和暂停、上一步和下一步、跳到任一步；现在第几步、一共几步（或时间）；声音开关 |
| 出处 | 让每句话都能核对 | 想核对时找得到，核完回到原处；不核对时不遮住画面和字 | 每条：来源名、原句（原文语言）、它撑起的是哪句大字或标注、打开日期或链接；当前这一步用到的那几条先出来 |
| 假设说明 | 说清例子里哪些是假设 | 不让人把示例当成真数据，把简化当成全部 | 示例数字、教学假设、简化掉了什么 |
| 亲手试（至少一镜） | 让他亲手做一下，自己看到结果 | 他做过一次，最难的那一步就懂了；不动手也会自己演示一遍再往下播 | 播放流程里那一镜的同一个画面上：一句话说清请他做什么、能动的东西、随之变化的画面和读数、一句为什么、重置、怎么接着往下看；他不动手时的自动演示 |
| 页面标题 | 让人认出这是什么 | 收到文件的人不打开也知道讲的是什么 | 具体的问题或答案，用在标签页标题和文件名上 |

如果你认为还有别的东西非常适合放进这个成品，能明显帮他理解，或能大大提升交互的体验，就放心发挥创意放进来。但所有规则和底线照样要守，不能为了炫技而加。

## 按卡点挑讲法

可以组合，但沿用同一套对象和颜色，换讲法不让人重新认画面：

- 看不见的过程、先后：同一个对象逐步变化，起始状态先完整出现。
- 想错了：先让他猜（亲手选一个），再演给他看，再对照。
- 内部结构：一层层拆开或剖开；只有转一下才看得懂时，才做能转的立体。
- 多个因素互相影响、不会算：就在那一镜里让他改一个条件，马上看到结果和为什么变。
- 想不出大小：带参照物的尺度推拉。
- 看不懂条文和单据：原文和白话并排，点哪处亮哪处，能回到原位。
- 对比：并排或原位切换，尺度和起点一致。
- 小游戏、分支故事：胜负和后果必须取决于要理解的那条规则。

用户点名的形式照做；要转发的按转发的地方做（发群就是手机竖屏、短、文件小）。

## 什么时候出视频文件

用户点名要视频，或要发群、投屏、放给孩子看。先写分镜（每镜：画面、大字或旁白、几秒、怎么接到下一镜；亲手试那一镜放它的自动演示），出几张关键帧自己看一遍，再出成片；竖屏横屏按看的地方定。视频也要有声音：背景乐和音效照 `风格.md`「声音」做进音轨（录屏通常录不到网页里的声音，要按画面的同一份时间表单独合成音轨，再和画面合到一起）；电脑上有现成语音就配音，背景乐在人声下面让开；没有就做字幕版，背景乐和音效照样要有，并说明没配音的原因；音轨合不进去时也要说明。关键内容放画面中间，四边留出被裁的余量。渲染工具没有时，照「一直要守的」先问，同意之前先交网页版。没有时长要求时讲清一个卡点就停，通常一两分钟内。
