# 计划：动手前先想清楚

下面每一项都要有答案，但不用写成文件，怎么想由你定。拿不准的项，按最可能的情况先定，在第一条消息里说出你的假设。原因：不想清楚就埋头做，成品常常讲对了知识、却答错了人——比如有人只想知道手上这件事该怎么看，拿到的却是一堂课。

## 要想清楚的几件事

1. **谁在问、拿去做什么。** 从他的原话、给的材料、你对他已有的了解（之前的对话、他说过的身份、年龄、处境）判断：他是想自己弄懂，想知道这对手上的事意味着什么，要讲给别人（孩子、学生、同事、家人），还是要转发到群里？最后看的人是谁、多大、懂多少、会在什么情况下看？
   - 同一个问题，学生问多半想学原理；正在做这件事的成年人问，多半想知道它对自己意味着什么。后一种不要做成一堂课，讲清他需要的那一点就够。
2. **他真正问的是什么。** 问题里有没有错误的前提、有没有把两件事混在一起、背后有没有更根本的那一问？前提错了，先讲清前提。
3. **卡点属于哪种机制。** 问自己：他脑子里缺的是哪一个画面？
   - 看不见：过程发生在体内、机器里、后台；
   - 想错了：直觉或流行说法给了错答案；
   - 想不出大小：数字太大、太小，或要换算；
   - 看不到里面：内部结构、由哪几部分组成；
   - 只看到一环：多个因素互相影响，只看一步会得出错结论；
   - 不会算：概率和统计；
   - 看不懂条文：字都认识，不知道指向什么（规定、表格、流程、条件分支）；
   - 想不出方位：空间关系、运动路径；
   - 想不出先后：时间差、累积、随时间变化。
   可以不止一种，挑最主要的一种来定讲法和形式。
4. **讲到多深算够。** 他要的是一个画面就够，还是一整套讲解？能用一个画面讲清的，不做成一堂课；要讲给别人的，按听的人的水平定深浅。
5. **讲法。** 主线只讲哪一点；用哪个具体的小例子走完全程；最难跨过的是哪一步、在这一步让他亲手试什么；结论在什么情况下不成立。细则见 `讲法.md`。
6. **形式和风格。** 做成什么、谁在什么设备上看、要不要能转发；大概要多久。然后想清楚画面：
   - **世界**：主角是什么东西、在什么现场、什么时候的光。
   - **风格配不配**：没点名风格时，列五个候选比出最合适的一个（见 `风格.md` 第 2 步）。这一题要让人看见的是哪种变化（形状变了、数量涨了、一层层叠上去、沿一条路走、拆开看里面……），哪种画面语言最擅长把它画出来；这种语言的气质和题目、和看的人配不配（严肃的健康题配吵闹的花字会显得轻佻，给孩子看的配冷冰冰的仪表界面会显得远）。
   - **色彩体系**：从主角本身的颜色、现场的光和时间、题目的情绪里推出来；几种颜色、谁是底、谁是主角、哪个只留给答案那一下。风格自带颜色传统的，想清楚这套颜色和你的题目配不配。
   - **声音**：背景乐的旋律是什么性格、用什么音色，这个世界里还会有哪些声音；题目的情绪和看的人适合多安静、多热闹（给孩子看的、要投屏的、讲钱和健康的，各不一样）。
   细则见 `形式.md`、`风格.md`。
7. **要查什么。** 哪些结论需要出处、该去哪类来源找、用户的说法里哪些要先核对。细则见 `出处.md`。

## 几条规则

- **要不要问用户**：只有一件你判断不了、又会让成品完全不同的事（通常是给谁看、拿去做什么），才在第一条消息里问，一次只问这一件；同时说清不回复会按哪种做，然后照它先做下去。能从原话推断的不问。
- **不替用户安一个他没有的误解。** 他心里的疑问，要从他的原话里找；他没说过的错误想法，不要当成他的卡点来纠正。
- **查完资料再对一遍**：查到的东西改变了你对卡点、用途或前提的判断，就改计划，不要硬按原计划做下去。
